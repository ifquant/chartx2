# 0045 - 让首页先收敛成 demo 风格工作台

这次提交的目标，不是继续在已有文档页上堆功能，而是先把首页的视觉重心改成更接近 `docs/demo.jpg` 的图表工作台。这样做的价值很直接：即使底层 engine 还在持续补齐，项目也已经开始朝最终产品形态收敛，而不是停留在“图表能力说明页”。

## 本次做了什么

1. 把首页从说明文档式布局改成了工作台壳
   - 增加了顶部工具栏、左侧工具栏、中心图表区、右侧 watchlist/detail/performance 面板、底部周期栏。
   - 中间仍然挂载现有 `chartx` harness，没有绕开当前 engine。

2. 保留并兼容了现有测试入口
   - 视觉测试仍然通过 `.chart-frame`、`.readout-bar` 和可见标题来定位关键区域。
   - Playwright 继续能通过 `/src/lib/chartx/public/index.ts` 动态导入 public API。

3. 让回归测试接受新的主界面形态
   - 更新了 API 和 harness 的截图基线。
   - HiDPI 校验从“严格相等”改成了“允许 1 像素以内误差”，避免被浏览器浮点尺寸抖动误伤。

## 为什么这样做

如果首页一直是“功能清单 + 示例画布”的结构，人很容易对项目的最终方向失去感觉。现在先把壳收敛到更像 TradingView 工作台，有两个好处：

- 你能更快判断整体方向是不是对的
- 后续做 pane、header、watchlist、study strip 时，不会一直在旧页面结构上返工

## 新人需要知道的两件事

1. Playwright 的元素截图会把元素当前真实尺寸一起录进基线  
   所以只要布局层级明显变化，即使图表内核没变，截图也必须重录，这不是测试失效，而是 UI 语义变了。

2. `devicePixelRatio` 相关断言最好避免写成绝对相等  
   浏览器里 CSS 像素和 canvas backing store 常常会有小数，最后取整时出现 1 像素误差很常见。对这类校验，用容差比硬等号更稳。
