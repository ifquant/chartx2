# 0045 - 减少卡片感，把主工作区收紧成桌面软件骨架

这次改的不是某个按钮样式，而是整个首页的空间组织方式。之前页面虽然已经有工具栏、图表区、侧栏这些元素，但组织它们的方式仍然像网页展示页：一层大卡片里面再嵌小卡片，依赖圆角、阴影、外边距和留白来表达层级。结果就是图表本体没有吃满空间，看起来不像交易软件，更像一个“图表 demo 页面”。

## 这次做了什么

1. 把顶层容器从卡片式壳改成分隔式壳
   - 去掉了顶栏和主工作区的大圆角、大阴影、大外边距。
   - 改成更接近桌面软件的整屏布局，用边线和固定栏位划分区域。

2. 收紧主工作区的垂直空白
   - 压缩了 toolbar、chart meta、readout、time strip、action strip 的高度。
   - 去掉了这些层之间原本靠 `gap` 撑出来的空白带。

3. 把右侧边栏从“多个独立卡片”改成“一个连续侧栏”
   - watchlist、symbol、activity 现在主要通过分隔线区分，而不是各自浮起来。
   - 这样视觉上会更像桌面终端里的 dock/panel，而不是网页仪表盘。

## 为什么之前会这么“网页化”

主要有三条：

1. 顶层容器自己就是一张大卡片  
   `padding + border-radius + box-shadow` 一起上，天然就会在四周制造缓冲带。

2. 内部区域继续套二级卡片  
   右栏的每个模块都是 `mini-card`，图表区下面的 readout 和 footer 也像独立胶囊区块，层级靠卡片而不是靠软件框架来表达。

3. 行高和间距按“阅读页”而不是“工作台”来设  
   顶栏、meta、footer、actions 都偏高，导致图表区被上下夹扁，留白显得特别多。

## 新人需要知道的两件事

1. 交易软件的“紧凑”不只是把 padding 调小  
   更关键的是先决定哪些区域是连续工作区，哪些区域只是被分隔线切开的功能带。骨架错了，微调 padding 只会让页面变成“更小的卡片页面”。

2. 视觉层级不一定要靠阴影和圆角  
   桌面工具类产品更常见的是边线、底色差异、固定栏位宽度和稳定对齐。这些东西更克制，但更像软件。

## 这次还没做

- 顶栏和侧栏还没有进入真正的桌面应用状态同步，比如窗口级菜单、真实 watchlist 交互、面板折叠
- workbench 默认页更像桌面软件了，但 feature tabs 还只是配套 demo 页面，不是最终工作台结构
