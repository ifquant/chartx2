# 0046 - 收紧右侧栏和底部工具带，继续减少“网页留白”

这次不是继续去掉圆角，而是处理更隐蔽的空白来源。上一轮虽然把整体从卡片页改成了分隔式工作区，但右侧栏和底部工具带里仍然保留了“网页展示页”的拉伸逻辑，所以内容少的时候，空白还是会自己长出来。

## 本次做了什么

1. 右侧栏从“均分高度”改成“内容驱动”
   - 原来 `workbench-sidebar` 用的是分数行高，watchlist、symbol、activity 会被强行拉成几块高盒子。
   - 现在改成 `auto auto auto minmax(0, 1fr)`，只有 activity 作为剩余空间区，前面的卡片都按内容高度收紧。

2. 补了一个真正的 pane strip
   - 新增了 `Panes` 区，显示 `Pane 1 / 2 / 3` 的紧凑列表。
   - 这样右栏中段不再是“价格块下面一大段空区”，而是有明确的软件信息结构。

3. 继续压缩主图上下工具带
   - 顶栏、图表 meta、readout、time strip、action strip 都继续降高。
   - 左工具栏按钮也进一步收小，主图区得到更多有效绘图面积。

## 为什么这一步很重要

做工具类桌面 UI，最容易犯的错不是“配色不对”，而是容器 sizing 逻辑错了。  
如果侧栏区域默认就是按比例瓜分高度，那内容再少也会显得像三张被拉长的网页卡片。真正的交易软件更像 IDE 或终端，信息块通常按内容高度贴边排，只有日志区、列表区、图图区去吃剩余空间。

## 新人需要知道的两件事

1. `fr` 在视觉上很危险  
   CSS Grid 的 `1fr` 很好用，但如果面板内容其实不多，它会把“空白”也当成需要被平均分配的布局结果。工具型界面里要很小心。

2. 面板里缺的不一定是内容，可能是结构名义  
   像这次的 `Panes`，不是为了多塞一个模块，而是为了让右侧栏中段有明确的信息用途，不再看起来像布局没完成。

## 这次还没做

- `Panes` 区现在还是静态结构条，还没有接 pane lifecycle 的真实状态
- 顶栏和底栏虽然更紧了，但还没有进入真正的桌面终端密度，比如更细的工具分组、状态分隔和 hover 行为
