# 0047 - 修正桌面工作台在缩放下过早塌成纵向页面

这次提交解决的是一个非常基础但很伤方向感的问题：`chartx2` 一旦在桌面窗口里缩放，右侧栏会过早掉到主图下面，整页变成长页面，看起来不像 chart workstation，而像一页被挤坏的文档站。

## 问题为什么会出现

之前首页壳虽然已经更像 demo 工作台，但响应式规则还带着“普通营销页/内容页”的思路：

- `1200px` 就让右侧栏掉到下一行
- 整个 workspace 高度跟着内容长，而不是优先占满桌面视口
- 顶部说明文字没有做收缩，窗口一紧就会挤压其它区域

这导致桌面缩放时，布局会比预期更早崩成纵向流。

## 这次怎么修

1. 把桌面态 workspace 改成真正的单屏工作台
   - 桌面默认使用 `height: 100vh`
   - `shell` 填满剩余高度
   - 右侧栏自己滚动，而不是把整页越撑越长

2. 让顶部栏先收缩，而不是先把布局挤坏
   - 顶栏改成两列 grid
   - 标题支持省略号
   - 中等宽度下按钮和卡片缩小一点

3. 推迟右侧栏掉到底部的时机
   - 把 sidebar 下掉的 breakpoint 从较宽桌面改到更接近平板的宽度
   - 这样桌面全屏或轻度缩放时，仍然优先保持三栏工作台

## 新人需要知道的两件事

1. “像工作台”的布局，和“像普通网页”的布局不是一回事  
   前者通常优先保证单屏结构稳定，再把滚动收进局部面板；后者则更容易让整页自然变长。

2. 视觉回归不是只测颜色和内容，也会把元素真实尺寸录进去  
   所以这种布局修正即使没有改 chart engine，也必须重录相关 screenshot baseline。

## 这次还没做

- 顶栏和右侧栏还没有真实的交互折叠、拖拽或可记忆布局
- 这次只修了桌面工作台稳定性，没有进入更完整的 watchlist / detail 联动
