# 0049 - 让图表真正铺满工作区宽度

这次修的是一个很典型的“UI 看起来像布局问题，其实根在图表测量逻辑”的问题。主界面中间的 chart 区已经变宽了，但真正的绘图内容还停在左边一小块，右边留下大块空白。

## 根因

`chart-harness` 自己在测量布局时，把宽度硬限制在了默认宽度 `960` 以内。  
这意味着：

- 工作区容器再宽
- 右侧栏再稳定
- 页面看起来再像桌面软件

只要绘图层自己不肯变宽，主图就永远像被卡在左边。

## 这次改了什么

1. 去掉了 `measureLayout()` 里的宽度上限
   - 现在绘图宽度会跟随真实容器宽度，而不是被 `960` 封顶。

2. 保留稳定高度策略
   - 这次没有把高度策略一起推倒重来，仍然用稳定的宽高比，避免引入新的自反馈抖动。

3. 增加了容器级 resize 监听
   - 不再只依赖 `window.resize`
   - 当 chart 容器本身尺寸变化时，也会触发重新渲染

## 新人需要知道的两件事

1. 图表 UI 的“空白布局问题”，经常不是 CSS 一层能解决  
   如果 canvas 内部的 layout measure 有自己的上限或缓存，外层容器变宽了，图也不一定会跟着变。

2. `window.resize` 和“容器尺寸变化”不是一回事  
   在复杂工作台里，侧栏开合、布局切换、父层 grid 调整，都可能改变图表容器尺寸，但未必触发窗口尺寸变化。

## 这次还没做

- 还没有做更完整的 chart area / sidebar 联动布局系统
- 这次只修复了“绘图宽度不跟容器走”的问题，没有进入多图布局或可保存工作区
