# 0053: 把 chartx2 锁进无页面滚动的桌面工作区

这次改动的核心不是“再微调一点间距”，而是把 `chartx2` 的页面模型从网页改成桌面图表软件。

用户指出的问题很准：

- 这是一个展示技术分析图表能力的演示软件
- 主界面不应该继续往下长
- 不应该依赖页面滚动条去容纳主图、右栏和状态面板

## 这次改了什么

### 1. 锁定整个页面到视口内

在 [src/routes/+page.svelte](/Users/dev/workspace2/hc_apps/chartx2/src/routes/+page.svelte) 里把根布局改成：

- `html/body` 固定高度
- `body` 禁止页面滚动
- `.app-shell` 固定为 `100vh`
- 根容器改成 `grid`，顶部栏 + 剩余工作区两行布局

这样页面不再像普通网页那样自然向下撑开。

### 2. 主图和右栏改成“吃剩余空间”的布局

把下面这些区域都改成了 `minmax(0, 1fr)` 思路：

- 主内容区
- `layout-grid`
- `demo-card`
- `workbench-shell`
- `workbench-main`
- `context-rail`

这一步的关键是让图表区和右栏去瓜分当前可用空间，而不是谁内容多谁把页面拉长。

### 3. 压缩右侧信息结构

右栏原来是很多分散卡片往下堆，很容易把页面顶出滚动条。

现在把它收成 3 个更紧凑的区块：

- `summary`
- `dashboard`
  - readout
  - metrics
- `activity`
  - event log
  - note
  - current gap

这更符合桌面软件的“信息面板”而不是“网页卡片流”。

## 为什么这样改

因为图表软件和网页有一个很大区别：

- 网页可以靠整页滚动继续往下放内容
- 图表软件通常要求主工作区始终留在当前窗口内

如果把图表演示软件做成网页思维，主图会失去控制感，用户也很难形成“这是一个 chart terminal”的直觉。

## 验证

实际跑过：

- `pnpm check`
- `pnpm test:visual --update-snapshots`

## 给新人的 2 个补充知识点

### 1. `min-height: 0` 对 grid/flex 子项非常重要

很多“为什么布局明明是 grid，内容还是把容器撑炸了”的问题，根因就是子项默认最小高度不是 0。

给关键容器补上 `min-height: 0`，才会真正允许它们在剩余空间里压缩布局。

### 2. `overflow: hidden` 不是万能药

如果只是给最外层加 `overflow: hidden`，但内部布局还是按自然高度堆叠，问题只会从“能滚动”变成“内容被裁掉”。

真正有效的是同时做两件事：

- 限定页面高度
- 把内部主要区域改成按剩余空间分配的布局模型
