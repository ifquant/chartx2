# 0054: 去掉 feature 页右侧长栏，让图表例子回到同一舞台

这次修正的重点，不是新增图表能力，而是把 feature 页从“网页后台”拉回“图表软件”。

用户指出的问题很准确：

- `Series`
- `Panes`
- `Interactions`
- `Styling`

这些特性页不该再配一个全局右侧长栏。

因为一旦右栏继续单独占一列，图表主区域就会被压窄，看起来更像后台系统，而不像围绕图表展开的演示软件。

## 这次改了什么

### 1. feature 页不再使用全局右侧长栏

现在：

- `Workbench`
  - 仍然保留右侧面板
- 其它 feature tabs
  - 不再带全局右侧栏

这让图表主舞台重新回到中心。

### 2. 把 feature 页的信息收进主卡片底部

特性页原本右侧那几块：

- summary
- metrics
- activity

现在都收成了图表下方的一条紧凑 `feature console`。

这样布局更像图表软件里的状态带，而不是网页卡片堆。

### 3. 顶部与按钮条一起压紧

顺手也做了两件配套修正：

- 顶部栏三段式结构更紧凑
- feature 页按钮条改成自然靠左排列，而不是把一整行强行拉满

这能明显减少“表单页面感”。

## 为什么要这么做

因为 `chartx2` 的 feature tabs 本质上是在展示图表功能，不是在展示解释性面板。

当一个 feature 页同时有：

- 顶部导航
- 巨大图表
- 右侧解释栏
- 底部操作区

用户会先感受到“页面被拆成很多块”，而不是“这是一张图表及其行为”。

把信息压回主舞台内部之后，图表才重新成为主角。

## 验证

实际跑过：

- `pnpm check`
- `pnpm test:visual --update-snapshots`

## 给新人的 2 个补充知识点

### 1. 图表产品里，解释信息最好贴着图表，而不是远离图表

如果指标状态、交互结果、metrics 离图表太远，用户需要来回扫视，界面会显得分裂。

把它们收成图表附近的 console，理解成本会低很多。

### 2. “去掉一整列”通常比“把那一列做漂亮”更有效

有些布局问题不是美术问题，而是结构问题。

当某一列本来就不该存在时，再继续打磨它，只会让错误结构更稳定。
