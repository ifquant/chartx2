# 0055: 把 feature tabs 从“解释界面”拉回“默会使用界面”

这次改动不是新功能，而是一次更偏交互心理学的修正。

用户指出的问题是对的：

- 画面虽然已经不滚动了
- 但 feature 页依然有太多“解释自己”的痕迹
- 顶部太松
- 标题太像说明栏
- 指标说明和信息块还是在抢图表的注意力

如果按波兰尼的默会知识去看，这种界面最大的问题不是功能少，而是：

用户还需要“读懂界面在说什么”，而不是直接顺手用它。

## 这次改了什么

### 1. 顶部从“介绍条”压成“状态条”

现在顶部左侧不再是很像 landing page 的大标题块，而是更像软件状态区：

- `chartx2`
- `NDX`
- `NASDAQ 100`

这样用户看到的是“我当前在哪个标的上”，不是“这个页面想跟我解释什么”。

### 2. feature 页标题改成行内信息

原来 feature 页顶部是：

- 一个标题块
- 一段解释性 summary

现在它被压成了更像工具页的单行信息：

- 当前 tab 名
- 一句低权重的 summary

这一步很重要。因为人类在工具软件里更习惯“抬眼确认当前模式”，而不是停下来读一段说明。

### 3. feature console 再次降权

底部 `feature console` 还保留，但进一步做了降权：

- 更浅的视觉存在感
- 更小的标题
- 更短的文字
- 更紧凑的 metrics 结构

这样它还在，但不会抢图表主舞台。

## 为什么这更符合默会知识

默会知识强调的是：

- 人类很多操作不是靠显式说明完成的
- 而是靠反复使用后形成的“看一眼就知道该做什么”

对图表演示软件来说，这意味着：

- 图表应该是第一注意力中心
- 状态应该靠位置和权重让人自然理解
- 说明文字应该存在，但退后

如果 summary、label、介绍区太显眼，用户就会被迫切换到“读说明模式”。这会打断工具使用的自然感。

## 验证

实际跑过：

- `pnpm check`
- `pnpm test:visual --update-snapshots`

## 给新人的 2 个补充知识点

### 1. 很多时候不是“信息不够”，而是“信息太大声”

当界面已经有图表、操作按钮、状态值时，再加一堆同等视觉权重的说明文字，用户反而更难形成直觉。

### 2. 工具型产品的说明最好退到第二层

真正高频使用的软件，通常不是靠大段解释来建立可用性，而是靠：

- 稳定的位置
- 一致的层级
- 足够轻的状态提示

这就是默会知识在界面设计里的一个直接体现。
