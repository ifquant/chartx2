# 0056: 让桌面工作区在缩放后仍保持单行壳布局

这次修的不是图表能力，而是桌面壳自己的布局纪律。

用户给出的截图很明确：

- 这不是手机页面，也不是普通网站
- 这是一个桌面图表演示软件
- 缩放之后，顶部和控制区不应该先换行、再把主图往下挤

如果顶栏、tab、按钮条可以像网页一样自由换行，那么一旦系统缩放、窗口变窄、或者字体变大，整个界面就会先长高，再把真正重要的图表区域挤坏。对桌面软件来说，这是很差的默认行为。

## 这次改了什么

### 1. 顶栏改成真正的单行桌面条

顶部现在不再允许在桌面宽度下自由换行：

- `brand`
- `tabs`
- `status`

这三块会一直留在同一行里。

真正放不下的时候，优先策略不是“长高”，而是：

- 压紧间距
- 缩小状态块
- 让 tab 区自己横向滚动

这更像桌面软件，而不是网页导航。

### 2. tabs 和操作条统一改成“横向滚动，不换行”

这次把几类最容易在缩放后失控的条带都收成了同一个规则：

- 顶部 tabs
- workbench toolbar
- feature actions
- readout bar
- timeframe strip

它们现在都优先保持单行。

如果内容多，就在本区域内横向滚动，而不是把整个页面撑高。

### 3. 主工作区明确声明为“吃剩余高度”

除了顶栏之外，真正的工作区现在会继续吃剩余高度：

- `layout-grid`
- `demo-card`
- `workbench-shell`
- `workbench-main`

这些容器都额外补了 `overflow: hidden` 和更严格的 `min-height: 0` 语义，避免内部内容因为默认最小尺寸而把外层顶开。

### 4. 桌面和移动的规则重新分开

以前一些“为了小屏兜底”的行为会影响到桌面缩放场景。

现在规则更明确：

- 桌面优先：单行、锁高度、局部滚动
- 真正进入小屏断点后：才允许回到单列和换行

这能避免桌面缩放时误触发“网页式重排感”。

## 为什么这更符合默会知识

默会知识在这里的关键不是“少写说明”，而是：

用户对桌面工具有非常强的身体预期。

比如：

- 顶栏应该稳
- 图表应该一直占主舞台
- 局部条带该挤的时候挤自己，不该把整页结构打散

这些预期通常不是用户能说清楚的文档规则，但一旦违背，用户会立刻觉得“这不像桌面软件”。这就是默会知识在布局上的体现。

## 给新人的 2 个补充知识点

### 1. `min-height: 0` 在 grid 布局里非常关键

很多“内容把父层顶开”的问题，不是组件太大，而是 grid/flex 子项默认不愿意缩小。给需要收缩的子层补 `min-height: 0`，往往是桌面式单屏布局的必要条件。

### 2. 桌面软件更适合“局部滚动”，不适合“全页长高”

网页常见做法是让内容继续往下长。但桌面工具里，用户更希望：

- 主结构固定
- 主舞台稳定
- 次要信息在自己的小区域里解决拥挤

这就是为什么这次优先选择“单行 + 局部横滚”，而不是“自动换行 + 整体增高”。
