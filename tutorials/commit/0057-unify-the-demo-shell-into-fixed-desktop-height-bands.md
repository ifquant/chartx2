# 0057: 把 demo shell 统一成固定区块高度的桌面骨架

这次不是增加新功能，而是继续把 `chartx2` 从“网页式内容堆叠”拉向“桌面图表软件骨架”。

用户指出的问题很准：

- 即使已经禁掉了整页滚动
- 画面依然还有明显的网页感
- 顶部、workbench、feature tabs 之间的垂直节奏不统一
- 一旦缩放，界面容易显得像几块内容卡片堆在一起

这类问题不能靠继续减文案解决，得直接改布局模型。

## 这次改了什么

### 1. 根容器改成固定高度带系统

`app-shell` 现在不再是：

- 顶部按内容长高
- 剩下区域再随缘分配

而是明确变成：

- 一条固定高度的 `topbar`
- 一块吃剩余空间的工作区

也就是说，最外层先定义“哪几段空间存在”，再往里放内容。

### 2. workbench 和 feature card 都有了自己的固定行系统

以前 `demo-card` 只是一个大容器，里面各部分靠内容自然撑开。

现在变成了两套更明确的桌面分段：

- `workbench-card`
  - 固定高度标题区
  - 剩余空间给主工作台
- `feature-card`
  - 固定高度标题区
  - 主图区
  - 固定高度 readout
  - 固定高度 action strip
  - 固定高度 feature console

这样每个 tab 切换时，用户看到的是“同一块软件壳里换了模式”，而不是“打开了另一张不同长度的网页”。

### 3. workbench 主舞台也被切成固定带

`workbench-main` 现在明确分成：

- 顶部行情信息条
- 中间主图区
- readout 条
- footer 控制区

这能保证：

- 图表永远是剩余空间的主要消费者
- readout 和 controls 不会因为内容多寡临时变成大块说明面板

### 4. feature console 不再只是“跟着内容走”

`feature-console` 现在也有固定高度带。

这样 `Summary / Metrics / Activity` 这类内容会被约束在自己的区域里，不会在某些 tab 上突然长高，破坏主图和控制区的节奏。

### 5. 小屏断点和桌面断点被更明确地分开

桌面规则现在更强：

- 优先固定高度
- 优先单屏分带
- 优先局部容器自己解决拥挤

只有在真正进入窄屏断点时，才回退到更自由的行高和单列布局。

## 为什么这更符合默会知识

波兰尼的默会知识在这里体现在：

用户对桌面工具的“空间结构”有隐含期待。

他们未必会说出：

- 顶条应该多高
- 控制区应该几段
- 控件之间如何对齐

但他们会立刻感觉到：

- 这个软件是不是“稳”
- 它是不是一个可反复使用的工作台
- 它是不是像网页一样到处在变形

固定区块高度系统的作用，就是把这种隐含期待落成明确结构。

## 验证

实际跑过：

- `pnpm check`
- `pnpm test:visual --update-snapshots`
- `pnpm build`

## 给新人的 2 个补充知识点

### 1. “固定高度”不是僵化，而是建立空间纪律

对桌面工具来说，固定区块高度的价值不在于视觉整齐，而在于用户能快速形成身体记忆：标题在哪、图在哪、控制在哪。

### 2. 先定义空间带，再放内容，通常比反过来更像软件

网页常见思路是内容先长出来，布局再适应。

而工具软件常常相反：

- 先定义结构
- 再让内容住进去

这也是为什么这次改动会明显减少“网页感”。
