# 0058: 阻止 chartx2 在缩小窗口时掉进网页断点布局

这次修的是一个真正的根因，不是表面样式。

用户反馈是：

- 窗口一缩小
- 主界面就像没有布局一样
- 整个壳开始变成网页式堆叠

这不是“用户要求太高”，而是我们之前的默认假设错了。

`chartx2` 是桌面图表演示软件，不是响应式官网。  
如果窗口稍微小一点就掉进单列、解释卡片、状态条占整行，那用户自然会觉得它不像软件。

## 根因是什么

有两个问题叠在一起：

### 1. Tauri 默认窗口太小

之前默认窗口还是：

- `800 x 600`

这会直接触发页面里给小屏写的断点逻辑。  
也就是说，软件一启动，就已经在“偏网页、小屏”的布局区间里了。

### 2. Workbench 里还残留着网页式解释区

页面里还保留了这些不该继续主导桌面的东西：

- `完整工作台例子`
- 额外的 `summary / note / current gap` 解释块
- 已经没用但还在影响结构的右侧 `context-rail` 相关样式

它们在大窗口里也许只是显得啰嗦，在小窗口里就会直接把主界面打散。

## 这次改了什么

### 1. 把桌面窗口默认尺寸抬到真正可用的范围

`src-tauri/tauri.conf.json` 现在把主窗口改成了：

- 默认 `1440 x 900`
- 最小 `1120 x 760`

这一步很关键。因为它把软件的“默认生存区间”拉回了桌面工具该有的范围。

### 2. 去掉 Workbench 的解释性外壳

Workbench 现在不再额外展示：

- `完整工作台例子`
- 右侧独立 `context-rail`
- 那些 summary / note / current gap 卡片

保留的是更像软件本体的部分：

- 图表
- 右侧 watchlist / detail / activity
- 控制条
- readout

### 3. 布局不再假装自己还有第二列

之前主布局还保留着一个已经没内容的第二列定义。  
现在 `layout-grid` 已经收回成真正的单列主舞台，不再平白为旧右栏预留空间。

### 4. 断点被压回更像桌面软件的区间

不是一缩就掉，而是：

- 更晚才进入真正的小屏模式
- 先压缩局部区域
- 最后才单列

这更符合桌面用户的直觉。

## 为什么这更符合默会知识

默会知识在这里的关键是：

用户并不会先分析 CSS 断点和窗口尺寸。  
他只会直接感觉：

- 这个软件稳不稳
- 缩小一点会不会散掉
- 主图是不是一直是主角

一旦软件在默认窗口或稍小窗口里就像网页一样重排，用户马上就会失去“这是桌面工具”的身体信任。

所以这次修的是一种更底层的使用感：

让用户不用理解布局规则，也自然觉得这个界面是稳的。

## 验证

实际跑过：

- `pnpm check`
- `pnpm test:visual --update-snapshots`
- `pnpm build`

## 给新人的 2 个补充知识点

### 1. 桌面软件的默认窗口大小，本身就是交互设计的一部分

如果默认窗口太小，很多布局 bug 根本不是 CSS 小问题，而是软件从第一秒就被放进了错误的使用场景。

### 2. 删除“解释自己”的区块，往往比继续美化它更有效

当一个界面已经开始像说明页时，最好的办法通常不是把说明卡做得更漂亮，而是先问：

- 这块是不是根本不该继续存在？

这次答案就是，很多块不该存在了。
